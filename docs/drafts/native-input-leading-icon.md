# 입력란에 아이콘을 추가할 때 왜 입력 자체는 그대로 둬야 할까?

작성자 검토용 초안. 공개 근거: [Oddmash UI #169](https://github.com/Oddmash/oddmash-ui/issues/169).

검색창에 돋보기 아이콘을 표시한다는 요구가 있었습니다. 화면만 보면 아이콘을 넣고 여백을 맞추면 끝날 것 같습니다. 하지만 아이콘을 표시하는 조건에 따라 입력 요소 자체가 교체되면 어떤 일이 생길까요?

## 외형과 입력의 계약은 구분합니다

입력값과 DOM 포커스, 폼 이름, ref, disabled 속성은 아이콘이 있든 없든 같은 입력을 가리켜야 합니다. 아이콘이 장식이라면 스크린 리더의 별도 탐색 대상이 되거나 클릭을 가로채지 않도록 합니다. 검색창의 접근 가능한 이름은 장식 아이콘과 별개로 제공해야 합니다.

#169의 제안은 기존 Input에 선택적으로 leadingIcon을 받아 논리적 inline 시작 위치에 장식을 배치하는 것입니다. 기존 입력 API와 네이티브 동작을 유지하는 것이 요구사항입니다. 이는 실제 구현 결과가 아니라 공개 이슈에서 확인한 설계 조건입니다.

## 검증에서 보고 싶은 것

- 아이콘 없이 기존 Input을 사용해도 기존 동작을 유지합니다.
- 입력 도중 아이콘을 표시하거나 숨겨도 포커스, 입력값, 폼 제출값이 유지됩니다.
- 오른쪽에서 왼쪽으로 읽는 레이아웃에서도 inline 시작 위치를 지킵니다.
- 비활성 상태에서 아이콘으로 인해 새로운 조작 경로가 생기지 않습니다.

공개 전 실제 출시 API 및 관련 PR의 검증 결과를 연결하고, 아이콘 변경 전후의 포커스와 DOM 요소를 비교하는 실습을 추가할 것. 관련 글 후보: 제어형 입력, 재사용 가능한 컴포넌트의 API, 버튼과 링크.
