# 링크의 참고 설명을 Tooltip으로 보여줄 때 무엇을 지켜야 할까?

작성자 검토용 초안. 공개 근거: [Oddmash UI #152](https://github.com/Oddmash/oddmash-ui/issues/152).

여백의 참고 자료 링크는 읽던 흐름을 유지하면서 출처의 내용을 확인할 수 있어야 합니다. 기존 title 속성은 브라우저에 맡기는 방식이지만, 표시 시점과 스타일을 제어하기 어렵습니다. 그렇다고 링크를 새로운 버튼으로 바꿔버리면 링크의 클릭, 키보드 탐색, 새 탭 열기 등 기존 사용법까지 달라집니다.

## 링크와 설명은 다른 역할입니다

링크는 이동을 담당하고 Tooltip은 추가 설명을 제공합니다. Tooltip이 열리더라도 포커스는 링크에 남아야 합니다. 이미 aria-describedby가 연결된 링크라면 새 설명의 ID를 추가하고, 정리할 때 다른 설명을 제거하지 않아야 합니다.

## 마우스만 확인하면 놓치는 조건

| 입력 | 확인할 결과 |
| --- | --- |
| Tab | 링크에 포커스가 가고 필요한 설명을 확인할 수 있음 |
| Escape | 설명만 닫고 포커스 유지 |
| 포인터 이동 | 설명 영역에 접근하는 중 갑자기 사라지지 않음 |
| Enter | 원래 링크의 이동 계약 유지 |

#152는 React에서 사용하는 컴포넌트와 정적 HTML 링크에 연결하는 controller를 함께 제공하는 방향을 제안합니다. 이를 통해 Astro 문서에서 이미 만들어진 링크를 유지할 수 있습니다.

## 구현과 검증에서 확인할 점

설명이 뷰포트 밖으로 넘어가지 않도록 위치를 조정하되 링크 위치 자체를 바꾸지 않습니다. 라우터로 문서를 이동했다면 이전 링크의 이벤트와 설명 요소도 정리합니다. Tooltip은 추가 설명에 적합하지만 반드시 읽어야 하는 정보나 조작 버튼을 숨기는 용도로 쓰지 않습니다.

공개 전 현재 릴리스의 실제 API와 동작, 테스트 결과 및 소스 링크를 대조하고 예제를 추가할 것. 관련 글 후보: 접근성의 버튼과 링크, 모달 포커스, 디자인 시스템의 컴포넌트 API.
