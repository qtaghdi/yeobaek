# 여백 기획

> 아는 것과 이해하는 것 사이의 여백을 채웁니다.

## 목적

프론트엔드 개발자가 놓치기 쉬운 디테일과 동작 원리를 설명하고 직접 재현하는 한국어 기술 노트. 일회성 시리즈 대신 주제별로 탐색 가능한 아카이브를 지향한다.

## 콘텐츠

| 분류 | 초기 범위 |
| --- | --- |
| 웹과 접근성 | 시맨틱 HTML, 버튼과 링크, 포커스 링, tabindex, 키보드, ARIA, 모달 포커스 |
| CSS | 쌓임 맥락, flex 넘침, cascade, viewport, scrollbar, 레이아웃 |
| 브라우저 | DOM 이벤트, 스크롤, 스토리지, 폰트와 크기 변화 |
| UI/UX | 타이포그래피, 시각적 위계, 여백, Skeleton, 피드백 |
| React와 상태 | 컴포넌트 API, 상태, effect, hook, portal, 서버 상태, URL 상태 |
| 디자인 시스템 | 토큰, 테마, variant, 접근성, 문서화, 호환성 |
| 아키텍처와 품질 | 모듈 경계, 폴더 구조, 모노레포, 테스트, 배포 |

모든 주제는 작성자가 직접 설명할 수 있는지 확인한 뒤 공개한다. Fiber, V8, JIT, 렌더링 엔진 내부 구현, GPU 및 WebGL, AST 및 컴파일러는 별도 검토 후보로 두며 사용 경험만으로 이해를 단정하지 않는다.

### 문서 구성

1. 문제와 관찰 결과
2. 동작 원리
3. 재현 또는 비교
4. 해결 방법과 한계
5. 관련 주제 및 공식 참고 자료

문서에는 Concept, Experiment, Comparison, Case Study 유형을 사용할 수 있다. 모든 문서에 실험이 필요한 것은 아니다. 회사의 내부 코드 대신 독립적으로 재현 가능한 예제를 사용한다.

## 디자인

공학 노트의 종이, 잉크, 여백을 현대적인 문서 UI와 결합한다.

| 역할 | Light |
| --- | --- |
| 종이 | `#F8F6EF` |
| 잉크 | `#292823` |
| 연필 | `#77746B` |
| 구분선 | `#DEDAD0` |
| 형광펜 | `#F4E89B` |
| 교정 표시 | `#B94A42` |

형광펜은 핵심 문장, 빨간 펜은 교정과 주의, 옅은 모눈은 실험 영역에 제한한다. 색만으로 상태를 전달하지 않고 대비를 검증한다. 다크 테마는 별도 의미 토큰으로 설계한다. 과도한 장식과 모션, 손글씨 본문, 보라색 브랜드 강조는 피한다.

헤더에는 브랜드, 검색, 테마, GitHub를 둔다. 좌측은 주제 탐색, 본문은 읽기와 실험, 우측은 현재 문서 목차로 사용한다. 모바일에서는 탐색과 목차를 접을 수 있게 한다.

## 목표 구조

- `apps/docs`: Astro + Starlight, MDX
- `apps/storybook`: React + Vite + Storybook
- `packages/experiments`: 공유 실험 컴포넌트와 독립 재현 예제
- `packages/tokens`: SCSS와 의미 기반 디자인 토큰
- `packages/config`: 공통 개발 설정
- pnpm Workspace + Turborepo

GitHub Pages에는 문서를 루트, 실험실을 하위 경로에 배포한다. 기존 세 실험과 ID를 유지하고 새 위치에서 접근 가능한지 확인한다.

## 진행 순서

1. 브랜드와 기획 확정
2. 모노레포 전환 및 기존 Storybook 검증
3. 문서 UI와 공통 실험 레이아웃 구현
4. 기존 세 실험과 문서 연결
5. 작성자 검토를 거친 초기 콘텐츠 추가
6. 빌드, 검색, 키보드, 반응형 및 Pages 경로 검증

모노레포 전환과 초기 세 실험의 문서 연결을 진행 중이다. 새 콘텐츠는 작성자 검토 후 공개한다.
