## 브라우저 확인

Node 24.22.3 / pnpm 11.25.0 / Playwright 1.62.1 / headless Chromium 158.0.8127.0, Linux. 변경 전 main 빌드와 변경 후 빌드의 320px 다크, 390px 라이트, 1280px 라이트에서 네 문서를 열었다. 본문 가로 넘침이 없었으며 기존 성공 시나리오의 종료 결과 A/B를 유지했다. A 실패는 A 오류/B 결과, B 실패는 A 결과/B 오류였다. Tab, Space, Enter로 실패 시나리오를 실행하고 포커스 링을 확인했다. 모듈 경계와 테스트는 기존 라디오의 실제 출력도 확인했다.

비동기 글의 '앞의 예제에서' 문단을 동일한 원문으로 비교했다. 390px와 1280px에서 Juliya 적용을 확인했고, 320px에서는 CSS fallback으로 읽을 수 있었다. JavaScript 비활성 상태에서 세 너비 모두 원문과 가로 폭이 보존됐다. 마지막 줄의 폭은 각 문단 최장 줄 대비 약 79~89%(스크립트 활성), 80~100%(비활성)였다. 대표 표는 인증 상태의 새 구분이 좁은 화면에 표시되는지 전후 스크린샷으로 확인했다. 물리 디바이스와 Safari, Firefox의 실제 동작 및 보조 기술 사용성은 이 점검에서 검증하지 않았다.

PR의 CI와 리뷰, main 병합 및 실제 배포 상태는 PR에서 별도로 추적한다. 다음 검토에서는 느린 스크립트 응답의 초기 예제 조작과 인증 흐름의 갱신·다중 탭 정책을 기존 근거에 따라 검토할 수 있다.
