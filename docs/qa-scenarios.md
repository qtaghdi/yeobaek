## 테스트 운영

- 사용 장면을 재현할 때 누르는 키만 표시합니다. 포인터 위치와 모양, 누르고 떼는 상태, 실제 동작의 결과가 원인 순서에 맞게 이어지는지 확인합니다. 좁은 화면, 일시 정지, 모션 감소 상태에서도 입력과 결과를 구분할 수 있어야 합니다.
- 테스트 간 독립성 및 재현성을 갖춥니다. 제어할 수 있는 네트워크 응답과 시간은 결정적으로 제어하고 임의의 긴 대기나 반복 재시도로 실패를 숨기지 않습니다.
- `pnpm build` 후 `pnpm test:build`로 공개 경로·앵커·인용·목차를 확인합니다. `pnpm test:browser`는 `PLAYWRIGHT_MODULE`에 Playwright의 `index.mjs` 절대 경로를 지정하며, `LAYOUT_SCREENSHOT_DIR`로 비교 화면을 저장할 수 있습니다. 브라우저 매트릭스는 `tests/browser-matrix.mjs`와 CI의 `full_browser_matrix` 수동 입력을 사용합니다.
- 핵심 필수 테스트를 PR에서 유지하되 비용에 맞춰 추가 브라우저·기기·탐색 검증의 범위와 수동 실행 조건을 분리합니다. 실패한 테스트를 삭제하거나 전체 검증으로 표시하지 않습니다.
- 실제 기능 결함을 재현하면 해당 기존 이슈를 업데이트하거나 중복 없이 새 이슈를 생성합니다. 여러 이슈가 한 원인이라면 근거를 연결합니다.
