공통 버튼을 다섯 화면에 만들고 나서 배경색을 바꿔달라는 요청이 들어왔습니다. 파일을 다섯 개 찾아서 고치면 됩니다. 근데 다음번엔 열 개라면요? 같은 결정을 반복하고 있다면 그 결정을 공유하는 방법부터 고민할 필요가 있습니다.

## 색상 이름보다 색상의 역할

```css
:root {
  --gray-900: #292823;
  --gray-100: #f8f6ef;
  --text-primary: var(--gray-900);
  --surface-default: var(--gray-100);
}
[data-theme="dark"] {
  --text-primary: var(--gray-100);
  --surface-default: var(--gray-900);
}
```

컴포넌트는 현재 테마의 구체적인 색보다 `--text-primary`와 같은 역할을 사용합니다. 색상뿐 아니라 간격, 크기, 테두리, 모션도 일관된 역할로 관리할 수 있습니다.

원시 토큰은 색상 자체를 표현하고 의미 토큰은 색상의 목적을 표현합니다. 회색 900을 쓰던 텍스트가 다크 테마에서는 밝은 색을 사용하더라도 컴포넌트는 같은 text-primary를 참조할 수 있습니다. 테마가 바뀌었다고 모든 버튼과 입력 필드를 수정할 필요가 없어집니다.

## 모든 값을 토큰으로 만들 필요는 없다

여러 곳에서 동일한 디자인 결정을 공유하거나 일관된 운영이 필요한 경우 토큰으로 만듭니다. 단일 화면의 특별한 값까지 무조건 공통 토큰으로 만들면 오히려 이름만 늘어납니다.

[Oddmash UI](https://github.com/Oddmash/oddmash-ui) · [MDN: CSS custom properties](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascading_variables/Using_custom_properties)

## 토큰은 누가 소유하는가

[Oddmash UI #116](https://github.com/Oddmash/oddmash-ui/issues/116)처럼 같은 역할을 하는 숫자가 곳곳에 흩어져 있으면 하나를 바꿔도 화면이 일치하지 않을 수 있습니다. 그렇다고 특정 페이지에서만 사용하는 특수한 배치까지 전역 토큰으로 만들어야 한다는 뜻은 아닙니다. 실제 공유하는 디자인 결정부터 이름을 붙여봅시다.
