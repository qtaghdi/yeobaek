`div`에 `onClick`을 넣으면 마우스로 눌렀을 때 버튼처럼 동작합니다. 그렇다면 굳이 HTML의 `button` 요소를 사용할 이유가 있을까요?

마우스만 사용하면 둘의 차이를 느끼기 어렵습니다. 하지만 키보드로 화면을 탐색하기 시작하면 이야기가 달라집니다.

## 브라우저가 이미 해주는 일

`button`은 동작을 실행하는 요소이고, `a[href]`는 다른 위치나 문서로 이동하는 요소입니다. 브라우저는 각 요소의 역할, 포커스 이동, 키보드 활성화 동작을 기본으로 제공합니다. 반대로 `div`는 일반적인 컨테이너입니다. 클릭 핸들러를 붙여도 자동으로 버튼의 의미나 키보드 활성화 동작이 생기지 않습니다.

예를 들어 제출 버튼과 페이지 이동 링크가 있으면 둘 다 같은 CSS 클래스로 꾸밀 수 있습니다. 그렇다고 HTML까지 같아야 하는 건 아닙니다. 링크에 주소가 있으면 새 탭에서 열 수 있고, 버튼은 Space로 활성화할 수 있습니다. 직접 재현할수록 브라우저가 이미 제공하는 동작을 놓치기 쉬워집니다.

## 키보드로 눌러봅시다

이 차이를 직접 확인해봅시다. 두 컨트롤 모두 마우스로 클릭하면 숫자가 증가하지만, Tab으로 이동한 뒤 Enter나 Space를 눌러보면 네이티브 버튼과 클릭 이벤트만 붙인 요소의 차이가 드러납니다. 왼쪽은 의도적으로 기본 키보드 동작을 구현하지 않은 예제입니다.

키보드로 누를 수 있게 만들려고 일반 div에 `tabindex="0"`만 추가했다면 포커스는 이동할 수 있습니다. 하지만 그 요소가 버튼이라는 의미가 생기거나 Space와 Enter로 활성화되는 것은 아닙니다. ARIA 역할을 넣는 것과 실제 키보드 동작을 구현하는 것도 별개의 일입니다. 그래서 기본 HTML 요소로 표현할 수 있는 경우에는 먼저 그 요소를 선택하는 것이 좋습니다.

## 버튼처럼 생긴 링크도 링크입니다

```html
<button type="button">저장</button>
<a href="/settings">설정으로 이동</a>
```

위 두 요소는 같은 스타일로 꾸며도 역할이 다릅니다. 폼을 제출하지 않는 버튼이라면 `type="button"`을 지정하고, 다른 페이지로 이동하는 요소라면 주소가 있는 링크를 사용하면 됩니다. 브라우저가 이미 제공하는 접근성 동작을 굳이 다시 구현하지 않아도 되죠.

[MDN: button](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/button) · [MDN: a](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/a)

## 페이지네이션은 버튼일까, 링크일까?

[Oddmash UI #41](https://github.com/Oddmash/oddmash-ui/issues/41)에서 다룬 페이지네이션처럼 실제 URL이 존재한다면 링크가 브라우저의 새 탭 열기나 주소 이동을 보존합니다. 반대로 현재 화면의 상태만 바꾸는 컨트롤이라면 버튼이 자연스럽습니다. 디자인이 아니라 행동을 먼저 정하면 HTML 요소 선택도 따라옵니다.
