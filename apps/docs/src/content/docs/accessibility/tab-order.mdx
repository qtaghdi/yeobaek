키보드로 화면을 탐색할 때 다음에 포커스가 어디로 이동할지 예측할 수 있어야 합니다. 카드가 눈에 보이는 순서와 Tab 순서가 다르면 화면을 이해하기 어려워집니다.

## tabindex의 의미

| 값 | 동작 |
| --- | --- |
| 기본 | 버튼, 링크, 입력 등은 브라우저가 정한 기본 순서에 참여 |
| 0 | 일반적인 순차 포커스 탐색에 참여 |
| -1 | 순차 탐색은 제외하지만 코드로 포커스 가능 |
| 양수 | 양수 그룹 안에서 값 순서로 우선 탐색 |

양수 값을 여러 곳에 주면 나중에 UI가 삽입될 때 전체 탐색 순서를 관리해야 합니다. 가능한 한 자연스러운 DOM 순서와 기본 HTML 요소를 사용합니다.

## 직접 확인하기

일반 순서와 두 번째 버튼에 -1을 적용한 상태를 전환한 뒤, 예제 안으로 Tab을 이동해 보세요. 양수는 문서 전체의 탐색 순서에 영향을 줄 수 있으므로 이 예제에서는 적용하지 않습니다.

## 주의할 점

포커스 이동 순서를 바꾸는 것과 화면을 읽는 순서를 바꾸는 것은 다른 문제입니다. CSS `order`로 시각적 배치만 바꾼다고 DOM 순서가 바뀌는 것은 아닙니다. 커스텀 위젯에서 한 항목만 Tab 순서에 남기고 방향키로 이동시키는 패턴은 별도 키보드 처리가 필요합니다.
