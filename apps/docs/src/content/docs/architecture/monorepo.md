공통 UI와 토큰을 여러 앱에서 사용하면 각각 라이브러리를 수정하고 버전을 배포하는 과정이 번거로울 수 있습니다. 하나의 저장소에서 여러 패키지를 함께 관리하는 방식이 모노레포입니다.

## 구성

```yaml
packages:
  - "apps/*"
  - "packages/*"
```

pnpm Workspace는 여러 패키지를 하나의 작업 공간에서 관리합니다. 내부 패키지는 workspace 의존성으로 연결하고 각 앱은 필요한 의존성을 명시합니다. Turborepo 등을 사용하면 패키지 간 작업 순서와 빌드 결과 캐시를 관리할 수 있습니다.

## 언제 적합한가

앱 사이에서 변경이 자주 함께 발생하고 공통 패키지가 실제로 사용될 때 장점이 있습니다. 독립적으로 배포해야 하는 프로젝트도 모노레포 안에서 분리된 빌드 작업을 구성할 수 있습니다.

반대로 앱 하나뿐이고 공유할 코드도 적다면 구조만 복잡해질 수 있습니다. 패키지 경계와 빌드 범위를 정하지 않으면 모노레포의 장점이 줄어듭니다.
