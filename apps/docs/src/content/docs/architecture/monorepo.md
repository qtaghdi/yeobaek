---

여러 앱에 같은 UI를 배포할 때마다 패키지 버전을 올리고 각 앱의 의존성을 다시 수정하는 작업을 반복하다 보면 하나의 저장소에서 관리하고 싶어집니다. 그런데 앱이 하나밖에 없다면 이야기가 조금 다릅니다.

## workspace로 무엇을 공유할까?

```yaml
packages:
  - "apps/*"
  - "packages/*"
```

pnpm Workspace는 여러 패키지를 하나의 작업 공간에서 관리합니다. 내부 패키지는 workspace 의존성으로 연결하고 각 앱은 필요한 의존성을 명시합니다. Turborepo 등을 사용하면 패키지 간 작업 순서와 빌드 결과 캐시를 관리할 수 있습니다.

workspace에 패키지를 둔다고 자동으로 의존성이 정리되는 것은 아닙니다. 앱이 직접 쓰는 패키지는 package.json에 명시하고, 공용 패키지가 앱 내부 구현을 역으로 import하지 않도록 경계를 정합니다. 그렇게 해야 여러 앱을 함께 변경하더라도 하나만 빌드하거나 배포할 수 있습니다.

## 앱이 늘어날 때 비로소 생기는 장점

앱 사이에서 변경이 자주 함께 발생하고 공통 패키지가 실제로 사용될 때 장점이 있습니다. 독립적으로 배포해야 하는 프로젝트도 모노레포 안에서 분리된 빌드 작업을 구성할 수 있습니다.

반대로 앱 하나뿐이고 공유할 코드도 적다면 구조만 복잡해질 수 있습니다. 패키지 경계와 빌드 범위를 정하지 않으면 모노레포의 장점이 줄어듭니다.

[pnpm: Workspaces](https://pnpm.io/workspaces) · [Turborepo](https://turborepo.dev/docs)

## 여백에서 모노레포 도구를 뺀 이유

여백도 처음에는 Storybook과 문서를 분리했습니다. 그런데 문서 안에서 예제를 바로 보여주는 방식으로 바뀌고 나니 별도 패키지와 Turbo를 유지할 이유가 사라졌습니다. [PR #5](https://github.com/qtaghdi/yeobaek/pull/5)에서 구조를 단순화한 이유입니다. 공유할 두 번째 소비자가 실제로 생기면 그때 다시 나눠도 늦지 않습니다.
