로딩이 끝나기 전후로 제목, 카드, 버튼의 위치가 크게 바뀌면 사용자는 화면을 다시 탐색해야 합니다. 데이터 표시 전에도 레이아웃의 형태를 고려합니다.

## 두 경우 비교

</ExampleFrame>

원본 화면을 예상하지 않은 작은 로딩 표시와 실제 카드 크기에 맞춘 스켈레톤을 비교합니다. 동일한 영역에서 로딩 완료 버튼을 눌러 요소의 위치가 얼마나 움직이는지 살펴보세요.

## 실제 구조에서 출발하기

- 카드와 표의 기본 프레임은 유지합니다.
- 로딩 시에도 제목, 예상 행 높이, 주요 컨트롤 위치를 최대한 맞춥니다.
- 로딩이 무한히 반복되거나 오류가 발생할 때 대체 상태를 제공합니다.

스켈레톤을 사용한다고 모든 레이아웃 변화가 사라지는 것은 아닙니다. 실제 데이터의 길이와 화면 크기가 다를 수 있으므로 좁은 화면과 긴 텍스트도 검증합니다.
