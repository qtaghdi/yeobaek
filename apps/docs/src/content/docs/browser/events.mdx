카드 전체가 상세 페이지 링크처럼 동작하고, 내부에 즐겨찾기 버튼이 있다면 두 행동이 함께 실행되지 않도록 구조를 먼저 확인해야 합니다.

## 이벤트가 전달되는 과정

이벤트는 조상에서 대상 방향으로 전달되는 캡처 단계, 대상 단계, 그리고 이벤트가 버블링하는 종류라면 다시 조상으로 전달되는 버블 단계의 순서로 처리됩니다.

`event.target`은 이벤트가 시작된 대상이고 `event.currentTarget`은 현재 실행 중인 핸들러의 요소입니다.

## 두 메서드는 목적이 다르다

`stopPropagation()`은 이후 전파를 차단하지만 기본 브라우저 동작을 막지 않습니다. `preventDefault()`는 취소 가능한 이벤트의 기본 동작을 막지만 전파는 계속될 수 있습니다.

먼저 중첩된 인터랙션 자체가 적절한지 확인합니다. 링크 안에 버튼을 넣는 대신 독립된 컨트롤로 분리하면 전파를 억지로 차단할 필요가 줄어들 수 있습니다.

[MDN: Event bubbling](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting/Event_bubbling)

## 프로젝트에서 이어진 고민

확장 프로그램의 요소 선택 모드에서는 Escape로 선택을 취소할 때 확장 UI의 상태와 실제 페이지의 상태를 함께 정리해야 했다. 이벤트의 대상, 전파 경로, 취소 여부를 구분해야 다른 페이지의 정상 동작을 방해하지 않는다.

### 검증 기준

이벤트를 처리하는 소유자를 명확히 하고 선택 모드가 아닐 때에는 개입하지 않는다. 이벤트 리스너 등록/해제와 aria-pressed 상태에서는 취소 이후의 최종 상태도 검증한다.
