카드를 눌러 상세 화면으로 이동하는 UI에 즐겨찾기 버튼을 달았습니다. 그런데 별을 눌러도 상세 페이지로 이동합니다. 버튼에 클릭 핸들러를 붙인 것만으로는 부모의 클릭 동작이 사라지지 않기 때문입니다.

## 클릭은 어떻게 이동할까?

이벤트는 조상에서 대상 방향으로 전달되는 캡처 단계, 대상 단계, 그리고 이벤트가 버블링하는 종류라면 다시 조상으로 전달되는 버블 단계의 순서로 처리됩니다.

`event.target`은 이벤트가 시작된 대상이고 `event.currentTarget`은 현재 실행 중인 핸들러의 요소입니다.

부모의 핸들러에서 클릭 대상을 확인할 수도 있지만, 모든 인터랙션을 그 안에서 예외 처리하기 시작하면 코드가 길어집니다. 기본 동작을 유지할 링크와 별도로 조작하는 버튼을 형제 요소로 두는 구조부터 생각해보면 좋습니다.

## 전파를 막는 것과 기본 동작을 막는 것

`stopPropagation()`은 이후 전파를 차단하지만 기본 브라우저 동작을 막지 않습니다. `preventDefault()`는 취소 가능한 이벤트의 기본 동작을 막지만 전파는 계속될 수 있습니다.

먼저 중첩된 인터랙션 자체가 적절한지 확인합니다. 링크 안에 버튼을 넣는 대신 독립된 컨트롤로 분리하면 전파를 억지로 차단할 필요가 줄어들 수 있습니다.

[MDN: Event bubbling](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting/Event_bubbling)

## 이벤트를 어디에서 책임질까?

Interaction Inspector의 요소 선택 모드에서도 페이지와 확장 UI의 이벤트를 구분해야 했습니다. [#26](https://github.com/Oddmash/interaction-inspector/issues/26)처럼 Escape를 처리하더라도 선택 중이 아닌 페이지의 정상 조작까지 바꾸지 않아야 합니다. 이벤트를 막기 전에 현재 어떤 기능이 이벤트를 소유하는지 먼저 생각해봅시다.
