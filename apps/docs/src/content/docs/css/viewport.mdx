PC에서는 높이 100vh로 잘 보이던 화면이 모바일에서 주소창 때문에 잘려 보입니다. 브라우저의 UI가 열렸다 닫혔다 하는 상황에서 우리가 말하는 화면의 높이가 항상 같은 것은 아닙니다.

## vh, svh, lvh, dvh

- `vh`: 뷰포트 높이 단위. 현대 CSS에서 기본 viewport 단위는 큰 뷰포트 기준과 연결됩니다.
- `svh`: 브라우저 UI가 펼쳐진 작은 뷰포트 기준.
- `lvh`: 브라우저 UI가 접힌 큰 뷰포트 기준.
- `dvh`: 브라우저 UI 변화에 따라 동적으로 변하는 뷰포트 기준.

```css
.dialog {
  max-block-size: 90vh;
  max-block-size: 90dvh;
  overflow: auto;
}
```

첫 선언은 지원하지 않는 브라우저를 위한 대체값입니다. 동적 단위는 크기가 바뀔 수 있으므로 스크롤 중 레이아웃 변화가 불편한 화면에서는 작은 뷰포트 기준도 고려합니다.

키보드가 화면을 덮는 경우는 브라우저와 기기 설정에 따라 달라집니다. 모든 문제를 dvh 하나로 해결한다고 가정하지 않고 실제 모바일 브라우저에서 확인합니다.

[MDN: CSS length](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length)

예를 들어 스크롤 가능한 모달의 전체 높이를 화면 높이와 동일하게 고정하면 짧은 화면에서는 내용 일부가 잘릴 수 있습니다. 최대 높이와 내부 스크롤을 함께 사용하면 콘텐츠를 읽을 수 있는 범위가 확보됩니다. 브라우저 주소창이 움직이는 상황에서도 버튼이 닿을 수 있는 곳에 남는지 확인해보세요.

## 화면을 채우는 것과 내용을 보여주는 것

최소 높이와 고정 높이는 다른 요구를 해결합니다. 화면 높이에 맞춰야 한다면 브라우저 UI가 변할 때 어떻게 반응할지를 정하고, 내용이 더 길다면 자연스럽게 스크롤할 수 있는 구조가 필요합니다.
