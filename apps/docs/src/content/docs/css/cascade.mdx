공용 버튼에 margin을 추가했는데 기존 스타일이 계속 적용됩니다. 이쯤 되면 !important를 넣고 싶어집니다. 다만 매번 그렇게 하면 다음번에 덮어쓸 사람은 더 큰 문제를 만나게 됩니다.

## 명시도보다 먼저 결정되는 것

CSS가 어떤 선언을 적용할지 결정할 때 무조건 명시도부터 비교하지는 않습니다. 같은 출처의 일반 선언이라면 cascade layer의 우선순위부터 확인합니다. 아래 예제에서 어느 padding이 적용될지 생각해봅시다.

```css
@layer reset, components, app;

@layer components {
  .button { padding: 12px; }
}

@layer app {
  button { padding: 8px; }
}
```

일반적인 명시도 비교만 생각하면 `.button`의 12px이 적용될 것 같습니다. 하지만 여기서는 `app` 레이어가 더 높은 우선순위를 가지고 있으므로 8px이 적용됩니다. 같은 우선순위에서야 명시도와 선언 순서를 비교하는 것이죠.

레이어 밖의 일반 선언은 레이어 안의 일반 선언보다 우선합니다. `!important` 선언은 중요도와 레이어 순서가 다르게 적용되므로 일반 선언과 같은 기준으로 판단하면 안 됩니다.

## 덮어쓰기 경쟁 대신 규칙을 정해보자

라이브러리 스타일을 억지로 큰 명시도로 덮기보다 reset, components, app처럼 의도적인 경계를 설정합니다. 공통 스타일에서 `:where()`를 이용해 명시도를 낮추면 사용자가 덮어쓰기 쉬워집니다.

모든 문제를 layer로 해결할 수는 없습니다. 개발자 도구에서 실제 적용된 규칙, 출처, 중요도와 명시도를 확인합니다.

[MDN: Cascade](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascade/Introduction) · [MDN: Specificity](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascade/Specificity)

## 공통 스타일은 어디까지 책임질까?

라이브러리의 스타일과 소비자 페이지의 스타일이 경쟁하지 않도록 역할과 우선순위를 정해두면 매번 선택자를 길게 만들 필요가 줄어듭니다. DevTools에서 실제로 어떤 선언이 이긴 것인지부터 확인하는 편이 좋습니다.
