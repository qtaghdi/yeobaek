# 시각 자료

- Specify the question, observable mechanism, initial state, causal input, intermediate transition and result before designing.
- Choose static diagrams for relationships, time-based animation for temporal ordering and interactive examples when readers benefit from choosing inputs. Avoid duplicating an existing example without adding insight.
- Use recognizable application surfaces, nested layers, meaningful arrows, source/target and numeric results, not generic cards floating in space. Keep UI identity, label orientation, spatial bounds and hierarchy stable across states.
- Make the one changing attribute visible; highlight the affected node or layer with shape, border and text, not color alone. Caption actual measured data separately from explanatory models.
- Keep the archive monochrome; use restrained semantic cues and shared typography. Avoid decorative chrome, repeated heading, redundant step badges and unnecessary automatic playback.
- For motion show input first, then response, hold the result and reset intelligibly. Provide pause, reduced-motion and no-script alternatives. Inspect initial, intermediate, completed and loop states using actual screenshots in supported themes and mobile widths.
- When a topic already has a scene, improve the mechanism or remove redundancy with evidence; don't merely add detail or animation.
