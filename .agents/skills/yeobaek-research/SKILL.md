# 근거 조사

- Identify the specific claim first. Use normative specifications, official docs, release notes and immutable project source or merged PRs. Record version and actual constraints; prefer original evidence over summaries.
- Separate proposed issue, implemented source, released package and deployed consumer. An issue description alone does not prove completion.
- Use publicly accessible evidence only. Never disclose private company implementation or invent project anecdotes, metrics or test results.
- For examples, use runnable code with exact inputs and observed output or label a model explicitly. Explain omitted production details.
- Add external URLs and Korean summaries to src/features/references/reference-catalog.mjs; validate links and citation coverage. Maintain existing public paths and anchors.
- Trace each consequential claim to evidence; mark uncertain claims as unverified and remove unsupported certainty. For teaching simulations, validate contracts against a real browser or authoritative documentation.
