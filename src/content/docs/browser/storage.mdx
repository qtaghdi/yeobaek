다크 모드로 바꿨는데 새로고침하자 다시 라이트 모드가 나옵니다. 이런 설정은 저장해두면 좋겠죠. 그런데 어제 잠깐 입력한 검색어까지 오늘 다시 나타난다면 어떨까요?

저장부터 하고 보기 전에 그 값이 어느 탭에, 언제까지 남아야 하는지 정해보겠습니다.

## 상태를 얼마나 오래 유지할 것인가

| 방식 | 일반적인 유지 범위 |
| --- | --- |
| React state | 컴포넌트 생명주기 |
| sessionStorage | 출처 및 탭의 페이지 세션 |
| localStorage | 같은 출처에서 브라우저 세션을 넘어 유지 |
| URL | 주소에 명시된 상태 |

`localStorage`와 `sessionStorage`는 모두 문자열을 저장합니다. 객체를 JSON으로 변환해서 넣을 수 있지만 읽을 때도 정상적으로 변환된다는 보장은 없습니다. 이전 버전의 설정이 남아 있거나 브라우저가 저장을 제한할 수도 있습니다.

예를 들어 화면 밀도를 저장하는 기능을 만들었다고 가정해봅시다.

```ts
const readDensity = () => {
  try {
    const value = localStorage.getItem("density");
    return value === "compact" ? "compact" : "comfortable";
  } catch {
    return "comfortable";
  }
};
```

위 함수는 저장된 값이 없거나 읽을 수 없어도 기본 화면 밀도를 반환합니다. 서버 렌더링 중에는 브라우저 저장소에 직접 접근할 수 없으므로 실행 환경도 구분해야 합니다. 저장소를 사용하지 못한다는 이유만으로 화면 전체가 실패할 필요는 없으니까요.

## 같은 주소인데 다른 값이 나오는 이유

출처(origin)는 스킴, 호스트, 포트의 조합입니다. 아래 예제의 가상 탭은 모두 같은 출처를 사용합니다. 같은 출처의 localStorage는 공유하지만, **sessionStorage는 출처뿐 아니라 최상위 탭의 페이지 세션으로 구분됩니다.**

목록 간격을 좁히고 임시 검색어를 저장한 다음 새로고침해 보세요. 두 값은 유지됩니다. + 버튼으로 독립 탭을 열면 간격은 유지되지만 검색어는 비어 있습니다. 기존 탭으로 돌아가면 방금 적었던 검색어를 다시 볼 수 있습니다. 기존 탭을 닫고 다시 열면 검색어가 사라집니다.

실제 새 창에 opener가 있으면 sessionStorage의 초기 복사본을 받을 수 있지만, 이후 변경은 독립적입니다. 이 예제는 opener가 없는 새 탭을 모델링하고 주소 이동 없이 본문에서 실험합니다.

| 조작 | localStorage | sessionStorage |
| --- | --- | --- |
| 탭 새로고침 | 유지 | 현재 탭 유지 |
| 독립 탭 추가 | 공유 | 빈 상태 |
| 이전 탭 선택 | 공유 | 해당 탭 값 |
| 탭 닫기 | 유지 | 닫은 페이지 세션 종료 |

위 실험은 메모리로 동작하는 모델이며 브라우저 세션 복원, 저장 용량, 저장소 차단, 다른 출처 및 파티셔닝 정책을 재현하지 않습니다. 실제 localStorage도 사용자나 브라우저가 지울 수 있으므로 영구적인 데이터베이스로 취급하면 안 됩니다. 실제 브라우저에서는 저장소 변경 이벤트가 변경을 일으킨 문서 자체가 아니라 조건에 맞는 다른 문서에 전달되므로, 자신의 UI는 직접 갱신해야 합니다.

[MDN: Web Storage API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API)

## 필요 없는 데이터까지 저장해야 할까?

[Interaction Inspector #13](https://github.com/Oddmash/interaction-inspector/issues/13)의 이벤트 타임라인처럼 분석에 필요한 정보만 남기는 편이 좋습니다. 저장할 수 있다는 것과 저장해야 한다는 것은 다릅니다. 특히 민감한 값은 환경설정과 같은 방식으로 취급하지 않습니다.
