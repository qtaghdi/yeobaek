## 40초 대신 시작과 끝을 보냅니다

4분짜리 곡이 21시 정각에 40초 지점까지 재생됐다고 해봅시다. 이대로 재생이 이어진다고 놓으면 곡은 20시 59분 20초에 시작한 셈이고, 21시 3분 20초에 끝납니다. 이 두 시각을 Discord 활동의 `timestamps.start`와 `timestamps.end`에 Unix 시각(초)으로 넣으면 진행률은 받은 쪽에서 현재 시각을 기준으로 계산할 수 있습니다. 21시 1분이라면 같은 시작 시각을 가지고도 1분 40초가 지났다는 것을 알 수 있죠.

```ts
const now = Math.floor(Date.now() / 1000);
const position = Math.max(0, Math.min(duration, observedPosition));
const start = now - Math.floor(position);
const end = start + Math.ceil(duration);
```

이 코드는 [프로젝트에서 재생 시간을 만드는 부분](https://github.com/qtaghdi/apple-music-discord-presence/blob/81cc2f87a5708e8f71f1bfd70635f25a6a63a489/src/presence.ts#L41-L48)을 설명하기 위해 입력과 시각 계산만 꺼낸 예입니다. 계산 전에 곡 길이가 0보다 큰 유한한 수이고, 재생 위치도 유한한 수인지 확인합니다. 위치가 유효한 숫자라도 곡의 범위를 벗어나면 0초에서 곡 길이 사이로 제한합니다. 시간 정보를 얻지 못한 곡은 제목과 가수는 표시하되 재생 막대에 필요한 시각을 생략합니다.

아래에서는 재생이 그냥 이어질 때와 곡 안에서 건너뛸 때, 오른쪽의 시각이 달라지는지 보면 됩니다.

여기서 시작은 재생 버튼을 처음 누른 시각과 항상 같지는 않습니다. 지금 이 속도로 재생이 계속된다고 할 때의 기준점입니다. 방금 2분 10초 지점으로 건너뛰었다면, 시작 시각도 그 위치에 맞춰 다시 계산해야 합니다.

## 시계를 다시 맞출 때가 있습니다

이전 확인 시점에 40초였고 그 뒤 5초 동안 계속 재생됐다면, 다음에 확인할 때는 45초 근처여야 합니다. 이 정도 변화라면 이미 전달한 시작 시각으로 충분합니다. 그런데 다음 관찰에서 2분 10초가 나왔다면 이전 기준점으로는 현재 위치를 설명할 수 없습니다.

프로젝트에서는 곡이 그대로일 때 이전 위치에 지난 시간을 더한 예상 위치와 새로 읽어 온 위치를 비교합니다. 차이가 2.5초보다 크면 탐색한 것으로 보고 활동을 다시 보냅니다. 2.5초는 이 도구에서 정한 판단 기준이어서, 그 이하로 움직인 탐색까지 모두 즉시 잡아내지는 않습니다. 곡이나 재생 상태가 바뀌는 경우에도 활동을 다시 계산합니다. [재생 상태를 읽고 갱신하는 코드](https://github.com/qtaghdi/apple-music-discord-presence/blob/81cc2f87a5708e8f71f1bfd70635f25a6a63a489/src/index.ts#L84-L108)

일시정지하면 위치는 그대로인데 시계는 계속 갑니다. 이전 시작과 끝을 남겨두면 표시하는 쪽은 노래가 아직 진행되는 것처럼 계산할 수 있습니다. 이 도구는 기본 설정에서는 잠깐 멈춘 곡의 활동을 지웁니다. 멈춘 곡도 표시하는 옵션을 켜면 제목과 가수는 유지하고 시각은 빼 둡니다. [일시정지와 진행 시각을 검증하는 테스트](https://github.com/qtaghdi/apple-music-discord-presence/blob/81cc2f87a5708e8f71f1bfd70635f25a6a63a489/test/presence.test.ts)

처음에는 현재 위치를 보내면 된다고 생각하기 쉽습니다. 막대를 계속 움직이게 하려면 시계에 기준을 잡아 줄 두 값이 필요했습니다. 시작과 끝을 주고, 곡을 건너뛰거나 멈춰 그 기준이 맞지 않을 때만 다시 맞추기로 했습니다.

## 시간이 흐르는 기준이 바뀌면

가상의 곡을 40초 지점에서 일시정지했다고 해봅시다. 시간이 10초 지나도 재생 위치는 40초에 머물러야 합니다. 시작과 종료 시각으로 진행 막대를 표현하는 모델은 재생이 진행 중일 때의 기준이며, 일시정지와 검색 이동 시점에는 상태를 새로 반영해야 합니다.

이 글의 공개 캡처는 실제 서비스 화면이고 시간 예시는 계산 원리를 설명하는 가정입니다. 실제 연동은 연결 대상이 지원하는 활동 표시 계약을 기준으로 검증합니다.
