스켈레톤 모양을 더 비슷하게 만드는 것부터 해야 할까요? 일단 로딩 전후에 카드가 얼마나 많은 공간을 쓰는지 확인해봅시다.

## 로딩 전후의 기하 구조

스켈레톤은 데이터를 기다리는 동안 보이는 콘텐츠의 형태를 예상할 수 있게 해 줍니다. 그 자체가 레이아웃의 문제를 해결하지는 않습니다. 첫 사례에서는 로딩 표시의 높이가 작고 완료 뒤 카드가 커지면서 뒤의 내용이 밀립니다. 두 번째 사례에서는 완료된 카드와 같은 최소 높이와 배치를 유지합니다.

실제 레이아웃의 변화는 높이뿐 아니라 콘텐츠의 폭이 달라져 텍스트가 추가로 줄바꿈되거나, 이미지의 고유 크기가 늦게 결정되면서도 발생합니다.

```css
.card {
  min-block-size: 8rem;
  display: grid;
  align-content: start;
  gap: .75rem;
}
```

카드 자체의 구조를 공유하고 로딩일 때 내부 콘텐츠만 대체하면 서로 다른 카드 두 개를 관리할 때 발생하는 크기 편차를 줄일 수 있습니다. 화면의 데이터 길이를 정확히 예상할 수 없다면 고정 높이로 문장을 잘라내기보다 최소 높이를 확보하는 것으로 시작합니다.

## 최초 로딩과 이미 표시된 데이터의 갱신

| 상태 | 표시할 UI |
| --- | --- |
| 처음 진입, 데이터 없음 | 실제 레이아웃을 예고하는 스켈레톤 |
| 이전 데이터가 있고 갱신 중 | 기존 내용 유지와 갱신 피드백 |
| 조회 결과 없음 | 실제 빈 상태와 필요한 다음 행동 |
| 실패 | 재시도할 수 있는 오류 상태 |

필터를 새로 적용했을 때 이전 결과를 계속 보여 줄지 비울지는 이전 결과를 새로운 조건의 것으로 오해할 위험과 읽기 흐름을 비교해서 선택합니다. 새 조건에 맞는 데이터가 아니라는 사실을 구분하지 않고 이전 결과를 그대로 표시하면 안 됩니다.

목록의 모든 데이터를 새로 받아올 때마다 로딩 UI를 표시하면 사용자는 검색 조건이 바뀔 때마다 보던 내용이 사라지는 경험을 하게 됩니다. 새 데이터가 기존 결과와 무엇이 다른지 알아야 하는 화면에서는 갱신 중임을 표시하고 결과가 준비된 순간 교체하는 쪽을 고려할 수 있습니다. 반대로 기존 조건의 결과가 새 조건으로 오해될 가능성이 높다면 그 상태를 명확히 나눠야 합니다.

## 이미지의 로딩과 실패

카드 목록에서 미리보기 이미지가 늦게 도착한다고 생각해 봅시다. 이미지가 로드될 자리에 크기를 미리 잡아 두면, 사용자가 읽고 있던 카드나 누르려던 버튼이 아래로 밀리는 일을 줄일 수 있습니다.

```css
.preview {
  aspect-ratio: 16 / 9;
  background: var(--surface);
}

.preview img {
  inline-size: 100%;
  block-size: 100%;
  object-fit: contain;
}
```

이 코드는 예시이며 모든 이미지에 16:9가 적합하다는 뜻은 아닙니다. 실제 자산의 비율과 필요한 표시 영역을 기준으로 geometry를 정합니다. 이미지 로딩에 실패했다고 계속 스켈레톤만 보여줄 이유도 없습니다. 기존 영역은 유지하되 이미지가 표시되지 않았다는 사실을 알아볼 수 있는 대체 상태를 제공해야 합니다.

## 접근성과 모션

[Oddmash UI #39](https://github.com/Oddmash/oddmash-ui/issues/39)에서는 스켈레톤이 실제 콘텐츠로 해석되지 않도록 접근성 상태를 다뤘습니다. 아직 존재하지 않는 가짜 제목이나 목록 항목을 화면 읽기 도구에 노출하지 않습니다. 시각 장식은 aria-hidden으로 처리하고 필요한 로딩 상태를 독립적으로 전달합니다.

자동 반복 shimmer는 상태를 알기 위한 필수 요소가 아닙니다. 모션 감소 환경에서도 로딩과 완료가 분명해야 하며, 실패 이후 무한 로딩이 남지 않도록 실제 비동기 상태와 연결합니다.

## 기다리는 동안에도 사용자는 화면을 보고 있다

로딩 중이라고 화면을 전부 가리는 게 항상 좋은 UX는 아닙니다. 이전 데이터가 이미 있다면 새 요청이 진행되는 동안 그대로 두는 편이 자연스러울 수 있습니다. 처음 조회하는 상황과 갱신하는 상황을 구분하면 불필요한 화면 전환을 줄일 수 있습니다.

데스크톱에서 맞춰둔 스켈레톤을 좁은 화면에서도 켜보세요. 실제 제목이 세 줄인데 자리는 한 줄만 잡혀 있거나, 이미지가 실패해서 카드 높이가 달라질 때 흔들림이 잘 보입니다. 카드가 차지할 공간도 결국 로딩 화면에서 결정해야 하는 일입니다.
