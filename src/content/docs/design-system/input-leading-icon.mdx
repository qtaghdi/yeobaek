검색창 앞에 돋보기를 붙이는 일은 간단해 보입니다. 그런데 검색어를 입력하는 동안 아이콘이 사라졌을 때 포커스까지 사라진다면 어떨까요?

여백의 검색 UI를 개선하면서 [Oddmash UI #169](https://github.com/Oddmash/oddmash-ui/issues/169)에 Input의 장식 아이콘 슬롯을 제안했습니다. 입력값, 포커스, 폼 제출과 ref가 그대로 유지되는 것이 요구사항이었습니다.

## 같은 입력을 계속 사용해야 합니다

아이콘이 있을 때만 입력을 다른 부모 요소에 넣는 구현은 조건이 바뀌면서 React가 기존 DOM을 교체할 수 있습니다. 비제어형 입력의 값이나 DOM 포커스가 사라질 수 있는 이유입니다.

[PR #170](https://github.com/Oddmash/oddmash-ui/pull/170)에서는 기존 Input 사용처를 위해 슬롯이 없는 경우의 마크업을 그대로 유지하고, 슬롯을 사용하는 경우에는 부모 구조를 유지했습니다. 이 기능은 [0.12.0](https://github.com/Oddmash/oddmash-ui/releases/tag/v0.12.0)에 포함되었습니다.

동적으로 아이콘을 표시할 때는 속성 자체를 제거하지 말고 `null`을 전달합니다. 다음 코드는 0.12.0 이상을 기준으로 한 축약 예제입니다.

```tsx
import { Input } from "@oddmash/ui/input";

const Search = ({ showIcon }: { showIcon: boolean }) => (
  <Input
    aria-label="검색"
    name="query"
    type="search"
    leadingIcon={
      showIcon ? (
        <svg viewBox="0 0 24 24" fill="none" stroke="currentColor">
          <circle cx="10" cy="10" r="6" />
          <path d="m15 15 5 5" />
        </svg>
      ) : null
    }
  />
);
```

슬롯을 선언한 상태에서 아이콘만 바뀌면 입력의 부모 구조와 DOM 요소가 유지됩니다. 반대로 슬롯 속성 자체를 추가하거나 제거하는 경우에는 동일한 유지 계약을 가정하면 안 됩니다.

## 장식이 새로운 조작 대상이 되어서는 안 됩니다

아이콘은 검색이라는 시각적 단서일 뿐 입력의 접근 가능한 이름을 대신하지 않습니다. 따라서 별도의 레이블을 제공하고 이미지가 클릭이나 키보드 입력을 가로채지 않도록 합니다.

CSS에서도 물리적인 왼쪽 여백 대신 논리적 방향을 사용합니다.

```css
.input-icon {
  position: absolute;
  inset-inline-start: 0.75rem;
  pointer-events: none;
}

.input-with-icon {
  padding-inline-start: 2rem;
}
```

위 CSS는 배치 원리를 설명하는 예시입니다. 실제 라이브러리는 디자인 토큰을 사용하고 아이콘이 있을 때에만 입력의 안쪽 여백을 조절합니다.

## 테스트는 무엇을 확인해야 할까?

| 확인할 값 | 기대 결과 |
| --- | --- |
| 입력 DOM | 아이콘을 바꿔도 동일한 요소 |
| 포커스 | 입력 중 아이콘만 변경하면 유지 |
| FormData | 입력값이 기존 name으로 전송 |
| ref | 실제 HTMLInputElement 참조 |
| RTL | 읽는 방향의 시작에 장식 표시 |

#170의 테스트는 아이콘이 없는 상태에서 입력하고, 아이콘을 추가했다가 다시 숨긴 후 동일한 요소와 값, 포커스가 남는지 확인합니다. 공개 릴리스 기록에서도 React 18과 19의 설치 검증이 확인됩니다.

공통 컴포넌트를 개선할 때는 화면에 보이는 결과뿐 아니라 소비자가 이미 의존하는 네이티브 동작까지 같이 고려해야 합니다.
