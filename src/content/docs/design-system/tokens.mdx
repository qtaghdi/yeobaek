버튼 배경을 바꿔달라는 요청이 왔습니다. 다섯 곳에 만들어둔 버튼이니 다섯 파일을 열면 되죠. 근데 다음 프로젝트에 버튼이 열 개 생겨도 그렇게 해야 할까요? 버튼마다 색을 정했던 것부터 다시 보게 됩니다.

## 색상 이름보다 색상의 역할

```css
:root {
  --gray-900: #292823;
  --gray-100: #f8f6ef;
  --text-primary: var(--gray-900);
  --surface-default: var(--gray-100);
}
[data-theme="dark"] {
  --text-primary: var(--gray-100);
  --surface-default: var(--gray-900);
}
```

위 코드처럼 컴포넌트에서 직접 참조하는 것은 회색의 숫자가 아니라 `--text-primary`라는 역할입니다. 원시 토큰에 실제 색을 두고 의미 토큰으로 그 색의 쓰임을 표현하는 것이죠.

밝은 테마에서 회색 900을 쓰던 본문이 다크 테마에서는 밝은 색을 사용하더라도 컴포넌트는 같은 토큰을 참조합니다. 테마가 바뀌었다고 버튼과 입력 필드를 하나씩 수정할 필요가 없어집니다. 간격이나 테두리, 모션도 같은 방식으로 공유할 수 있습니다.

## 모든 값을 토큰으로 만들 필요는 없다

여러 화면이 진짜로 같은 결정을 공유할 때 토큰을 꺼내면 됩니다. 지금 이 화면에서만 쓰는 값을 전부 토큰으로 올리면, 다음에 버튼을 바꿀 때 파일 대신 토큰 이름을 찾게 될 수도 있으니까요.

[Oddmash UI](https://github.com/Oddmash/oddmash-ui) · [MDN: CSS custom properties](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascading_variables/Using_custom_properties)

## 토큰은 누가 소유하는가

[Oddmash UI #116](https://github.com/Oddmash/oddmash-ui/issues/116)에서도 같은 역할을 하는 값들이 여러 위치에 흩어져 있는 문제가 논의됐습니다. 공통 컴포넌트의 간격을 변경할 때마다 각 사용처를 따로 수정해야 한다면 토큰을 공유하는 의미가 없어집니다. 어떤 값이 우연히 같은 숫자인지, 실제로 같은 디자인 결정인지 구분해보면 토큰의 범위를 정하기 쉽습니다.
