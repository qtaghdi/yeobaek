저장 버튼을 회색으로 바꾸고 커서도 `not-allowed`로 바꿨습니다. 이제 못 누를 것처럼 보이는데, 막상 눌러보니 저장이 됩니다.

직접 버튼을 만들 때는 이 두 가지를 따로 확인해야 합니다. 사용자에게 비활성이라고 알려주는 것과 저장이 실제로 막혔는지를요.

## disabled와 aria-disabled는 같은 말이 아니다

| 방법 | 실제 의미 |
| --- | --- |
| `disabled` | 지원하는 폼 컨트롤을 비활성화하고 일반 Tab 순서에서 제외 |
| `aria-disabled="true"` | 비활성이라는 의미를 전달하며 클릭이나 포커스를 자동으로 막지 않음 |
| `inert` | 영역과 그 하위 요소의 상호작용 및 포커스 탐색을 차단 |

특히 `aria-disabled`는 비활성이라는 의미만 전달한다는 점이 중요합니다. 버튼을 눌렀을 때 실행되는 코드는 직접 막아야 하고, 화면에서도 현재 조작할 수 없는 상태라는 것을 알아볼 수 있어야 합니다.

세 저장 버튼을 각각 클릭해 보세요. 가운데 버튼만 저장 횟수가 올라갑니다. 키보드로도 해볼까요? Tab을 누르면 첫 번째 버튼을 건너뛰고 가운데 버튼에 포커스가 갑니다. 한 번 더 눌러 마지막 버튼으로 이동한 뒤 Enter를 눌러도 저장 횟수는 그대로입니다.

## 사용자가 이유를 알아야 한다면

유효하지 않은 폼을 제출하지 못하게 하는 정도라면 네이티브 `disabled`가 간단합니다. 하지만 특정 메뉴를 이용할 수 없는 이유까지 키보드 사용자에게 알려줘야 한다면 포커스를 유지하는 방법을 고려할 수 있습니다.

반면 열린 모달의 뒤쪽처럼 화면의 한 영역 전체를 조작하지 못하도록 만들고 싶다면 개별 버튼을 모두 수정할 필요가 없습니다. 이런 상황에서는 `inert`가 다루는 범위를 생각해볼 수 있습니다.

[MDN: disabled](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/disabled) · [MDN: inert](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/inert)

비활성 버튼의 스타일만 공유하면 클릭을 막는 정책은 화면마다 다르게 작성하게 됩니다. 예를 들어 폼 제출을 막았는데 키보드 단축키나 다른 이벤트에서 같은 저장 함수를 호출한다면 상태를 UI에서만 확인하는 것으로는 충분하지 않을 수 있습니다. 버튼의 상태 표현과 실제 동작이 같은 조건을 바라보도록 구성하는 편이 이해하기 쉽습니다.

## 기본 입력 요소를 없앨 이유가 있을까?

Slider를 커스텀 스타일로 꾸며도 키보드 조작과 비활성화 기능까지 새로 만들 필요는 없습니다. [Oddmash UI #104](https://github.com/Oddmash/oddmash-ui/issues/104)에서처럼 실제 input의 상태를 기준으로 시각적 표현을 맞추면 브라우저가 제공하는 동작을 유지할 수 있습니다.
