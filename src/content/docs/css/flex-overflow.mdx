파일 이름 옆에 삭제 버튼을 붙였습니다. `report.pdf`로 확인할 때는 깔끔합니다. 그러다 띄어쓰기 없는 긴 이름 하나를 넣으니 삭제 버튼이 오른쪽으로 밀려납니다.

파일 이름에는 이미 `flex: 1`을 줬는데, 왜 안 줄어들까요?

## flex가 줄어들 수 있는 크기

Flex item은 일반적인 상황에서 콘텐츠의 최소 크기를 기본 최소 너비로 고려합니다. 따라서 끊어지지 않는 긴 파일 이름이 들어오면 남은 공간보다 더 큰 최소 너비를 가질 수 있습니다.

`flex: 1`은 여유 공간을 나누는 방식이지 최소 너비를 없애는 속성이 아닙니다. 파일 이름이 차지하는 공간을 줄이는 것부터 해결해야 삭제 버튼이 원래 위치에 남을 수 있습니다.

## 카드 폭을 줄여봅시다

조작 예제의 파일 이름과 열기 버튼을 살펴보세요. 카드 폭을 줄인 뒤 `min-width: 0`을 켜거나 끄면 이름이 들어갈 영역의 크기와 버튼의 위치가 어떻게 달라지는지 확인할 수 있습니다.

## min-width: 0이 하는 일

```css
.row { display: flex; gap: 8px; }
.name { flex: 1; min-width: 0; }
.name p {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
```

`min-width: 0`은 아이템이 줄어들 수 있게 하고, 말줄임은 넘친 텍스트를 표현하는 별도의 규칙입니다. 모든 텍스트를 숨겨야 한다는 뜻은 아닙니다. 전체 내용을 볼 방법이 필요하다면 줄바꿈이나 상세 보기를 제공합니다.

[MDN: min-width](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/min-width)

말줄임을 적용했는데도 보이지 않는 경우에는 말줄임을 표시할 요소가 실제로 얼마나 줄어들었는지 확인해보면 좋습니다. 여러 단계로 중첩된 flex 구조라면 텍스트의 부모뿐 아니라 그 상위 flex item의 최소 너비 때문에 축소되지 않는 상황도 있습니다. 개발자 도구에서 바깥쪽부터 실제 너비를 비교하면 어떤 요소가 공간을 차지하는지 확인할 수 있습니다.

## 말줄임과 스크롤은 별개의 문제

말줄임이 보이지 않는다고 자식 모두에 overflow를 숨기는 건 좋은 답이 아닙니다. 먼저 무엇이 줄어들어야 하는지, 무엇이 스크롤해야 하는지 정합니다. [Oddmash UI #121](https://github.com/Oddmash/oddmash-ui/issues/121)의 Select처럼 목록과 페이지의 스크롤을 분리하는 경우에도 같은 생각이 필요합니다.

## 숫자로 가용 공간을 계산해봅시다

가상의 카드 너비가 240px이고 열기 버튼이 72px, 요소 사이 간격이 12px이라면 파일 이름에 남는 공간은 156px입니다. 파일 이름의 자동 최소 너비가 190px이라면 여유 공간을 나눠도 그대로는 맞지 않습니다.

min-width: 0은 내용 자체를 자르라는 뜻이 아니라 아이템이 156px까지 줄어들 수 있게 합니다. 말줄임은 그 다음 단계입니다. 긴 파일 이름을 모두 읽어야 한다면 줄바꿈을 허용하고, 제목을 한 줄로 유지해야 한다면 전체 이름을 확인할 수 있는 다른 경로를 제공합니다.
