첫 화면을 화면 높이에 맞춰 `100vh`로 잡았습니다. 데스크톱에서는 멀쩡한데 모바일에서 열어보니 하단 버튼이 주소창 때문에 한 번에 보이지 않습니다.

화면 높이 전체를 썼는데 왜 전부 안 보일까요? 브라우저가 주소창을 접을 때도 같은 높이를 쓰는지부터 보겠습니다.

## vh, svh, lvh, dvh

- `vh`: 뷰포트 높이 단위. 현대 CSS에서 기본 viewport 단위는 큰 뷰포트 기준과 연결됩니다.
- `svh`: 브라우저 UI가 펼쳐진 작은 뷰포트 기준.
- `lvh`: 브라우저 UI가 접힌 큰 뷰포트 기준.
- `dvh`: 브라우저 UI 변화에 따라 동적으로 변하는 뷰포트 기준.

```css
.dialog {
  max-block-size: 90vh;
  max-block-size: 90dvh;
  overflow: auto;
}
```

첫 선언은 지원하지 않는 브라우저를 위한 대체값입니다. 동적 단위는 크기가 바뀔 수 있으므로 스크롤 중 레이아웃 변화가 불편한 화면에서는 작은 뷰포트 기준도 고려합니다.

예를 들어 화면 전체를 차지하지 않는 모달이라면 최대 높이를 제한하고 내부에서 스크롤할 수 있도록 만드는 편이 내용이 긴 상황에도 대응하기 좋습니다. 주소창이 움직이거나 화면에 키보드가 나타날 때도 버튼을 누를 수 있는 위치에 남는지 확인해야 합니다. 키보드에 대한 반응은 브라우저와 기기 설정에 따라 달라지므로 `dvh` 하나만으로 모든 경우를 해결할 수는 없습니다.

[MDN: CSS length](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length)

## 화면을 채우는 것과 내용을 보여주는 것

아래 버튼이 처음부터 보여야 한다면 주소창이 펼쳐진 상태에서 먼저 확인해보세요. 내용이 길어지는 경우에는 고정 높이보다 최소 높이를 주고 스크롤을 허용하는 편이 맞을 수 있습니다. 둘 다 열어보면 화면을 채우는 것과 내용을 다 담는 게 왜 다른지 바로 보입니다.
